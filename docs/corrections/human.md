# Loop 在哪里停住 — pi0 / RTX 5090 run-01

全程 46.794 → 27.556 ms,其中五次由人推动。这里分析**它为什么停在那几个位置**,
以及哪些能靠机制消除。

可以写成参考的技术事实已经收进 wiki,不在这里重复:PDL 的链条要求见
[hw-pdl-gdc](../../.agents/skills/kernel-wiki/wiki/hardware/pdl-gdc.md),
fixup 回程按哪一层存储计价见
[technique-stream-k](../../.agents/skills/kernel-wiki/wiki/techniques/stream-k.md)。
"估算写明存储层级"和"负面结论带工具箱"已是
[workflow](../optimization.md) 的复核条目。

## 1. 报告完就停 · −0.800 ms

**机制。** agent 把"有结果可汇报"当成自然边界。workflow 第 7 步其实已经写了退出
条件——主要热点接近有证据支持的可达能力、且无值得尝试的新方案——但它是散文,不是
一个必须回答的问题;而"我有话要说"是对话本能,每次都会赢。

**能消除。** 把退出条件变成停止前必须逐条回答的东西:每个主要热点现在在可达能力
的百分之几,以及为什么没有候选。答不上来就是没到。

**剩下的人:** 预算。但方向应该反过来——见末尾。

## 2. 把自己的负面结论归档为"已定论" · −0.847 ms

**机制。** loop 里没有任何环节会重看一条写完的结论,而结论写得越完整(有机理、有
扫描、有 commit),越像完成品。这次那条结论的两处支撑一个用错了存储层级,一个用了
早于三项关键手段的基线,但两者都不是算错,所以自查抓不到。

**部分能消除,而且可机械化。** 负面结论记录它当时的工具箱;当某个手段后来被实测
证明值一个量级,所有早于它的负面结论自动进入待重测清单。列出候选是机械的。

**剩下的人:** 判断某个新手段是否真的与某条旧结论相关。

## 3. 把阻碍当成世界的属性 · −1.785 ms

**机制,两层。**

其一,next-steps 写成了对世界的描述而不是工作计划。PDL 被搁置的理由完全准确——
需要生产者和消费者都是手写 kernel,而 cuBLAS 夹在几乎每一对之间——写下来却是
"it grows as more GEMMs become hand-written",没有任何让它发生的步骤。

其二更要命:agent 判定"需要一个能打过 cuBLAS 的手写 GEMM,不现实",**没有先查是否
已有库提供**。kernel-design 第 1 步写的是先查 Pi0/Pi0.5 和共享组件的已有实现——
只覆盖项目内复用,不覆盖上游库。

**根因是语料缺口。** 当时查过 wiki:症状指向 tile-scheduling,而那一页只讲整 tile
的调度,stream-K 在整个语料里不存在。于是得出"只能自己写"。现在 stream-K 页已补上
并指向 CUTLASS 的 swizzle,同一条查询下次会命中。**一个语料空洞直接变成了一次人为
介入**,这也是最容易还的一笔。

**剩下的人:** 是否愿意做"重写所有 cuBLAS 站点"这个规模的工作。

## 4. 为常规动作请示 · 0 ms

替换一个已上线的 kernel 前先征求同意。workflow 第 7 步的 model 外循环就是"每次只把
一个胜出候选接入当前最佳模型和 plan"——这是循环的常规动作。**完全能消除**,读到即可。

## 一次正确的停止

fp8 在 backbone gated FFN 上实测 2.34×,相对误差 3.7e-02 对 bf16 的 1.7e-03,而
`eval/tolerances.py` 只注册了 bf16 一种 precision policy。agent 没有自行决定,把分叉
交了出来。这次该停:它改的是部署的数值契约,`parity.md` 明确写着 a kernel task does
not invent one。**该停的是契约,不是结论。**

## 结论:默认方向是反的

| 能机械化 | 不可消除 |
|---|---|
| 停止前逐条回答退出条件 | 预算与胃口 |
| 负面结论带工具箱,工具箱变了自动进待重测 | 数值契约 |
| 被命名的阻碍同时写出移除代价 | 新手段与旧结论的相关性判断 |
| "只能自己写"之前先查上游库与语料 | |

本 run 的五次人为推动里,四次是"继续/再看一眼",只有一次是"停"——而那一次还是
agent 自己请示的。**说明默认设在了错的一端。** 应该是 loop 跑到文档写明的退出条件
为止,人的介入用来叫停;现在是 loop 停在任意一个可汇报的位置,靠人一次次叫它继续。

把 1 和 4 修掉,这个 run 里五次推动能省掉两次;3 的语料缺口已经补上;2 只能减轻,
不能消除。
